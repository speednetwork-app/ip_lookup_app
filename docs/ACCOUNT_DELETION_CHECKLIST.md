# 账户删除与服务前数据披露

实现日期：2026-11-05。Flutter 客户端；未改变 Bundle ID、VPN 扩展或计费金额。

## 用户流程

- 我的 → 删除账户。先核对实时账户信息，提供 Apple 订阅管理入口。
- 输入当前密码、勾选影响说明、最终确认后才发起删除；不自动退款或取消 Apple 续订。
- 无待结算资金：真实删除登录／个人资料、所有 Sanctum 会话、原订阅链接对应账户、非必要用量与工单；清理当前账号的本机购买日志、凭证及账号缓存。
- 有余额、佣金、开通中的 Web 付款或占用余额的待付款：仍可在 App 内提交请求，页面明确显示待结算，不虚报删除完成。既有资金结算流程不变；后台任务在结算完成后自动执行已确认请求。不会自动核销资金。
- 请求 UUID 与独立 256-bit 回执密钥让网络超时后可以只读核对结果；密码不持久化、不写日志，不自动重发删除 POST。
- Apple 财务交易、不可转让的原绑定及必要防重放标识保留。已删除账号收到有效续订通知仅记录交易，不恢复用户／流量／访问权限。
- 本机 IP 查询历史不属于账户资料，单独保留现有清除入口。恢复购买不会重新创建已删除账号。

## 接口

- `GET /api/v1/user/account/deletion`：鉴权、实时预览，不缓存。
- `POST /api/v1/user/account/deletion`：鉴权 + 密码重验 + 固定确认 + 3 次/分钟限流，只允许删除请求用户自身。
- `POST /api/v1/passport/account-deletion/status`：仅凭请求 UUID 和独立回执密钥读取最少结果，10 次/分钟，不返回邮箱、余额或用户标识。
- 删除事务和 Apple 交易沿用 user 行锁顺序。文件／缓存使用加密清单，成功后抹除清单内容；失败由专用 timer 重试。

## 私有后端运维（不放入公开站点）

服务器补丁、部署与 SQLite 测试在未发布的 `server/account-deletion`；生产删除 API 从不用于自动化测试。

- `php artisan account:deletion-pending`：只读待结算队列，不输出邮箱或密钥。运营需及时处理资金结算，避免请求无限等待。
- `php artisan account:deletion-cleanup`：完成已确认且资金结清的请求，重试文件／缓存清理，不调整任何余额或执行退款。
- `pikayun-account-cleanup.timer`：每 5 分钟执行专用命令，不启用或修改全局 Web 调度器。
- 不能通过回滚删除凭证表恢复已删除用户。备份恢复也必须重新应用删除凭证，不能重新激活旧账号。

## 数据披露

首次购买、恢复、Apple 套餐管理及首次 VPN 使用前展示统一的数据／接收方／用途说明；版本化确认后继续，拒绝不调用购买或连接。保留完整隐私政策入口。说明包含账号与用量、VPN 流量传输、Apple 交易、IP 数据提供商及地图提供商；不承诺未经核实的零日志或绝对匿名。

## 提审前仍需人工核对

实际金融资料的法定保留范围／期限及待结算请求处理时限，需要运营结合销售地区确认；实现不等于法律意见。App Store Connect 隐私标签、截图、审核账号及商品审核资料必须与实际功能一致。新客户端须重新构建后才能在真机出现删除入口；Windows 的 Flutter 测试不等于 iOS 构建和真机验收。
